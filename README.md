# Astro Health Monitor

Offline-first PWA for monitoring astronaut health: it works without internet (IndexedDB) and syncs with Supabase when a connection is available.

Built for NASA Space Apps 2026. UI in Spanish and English; code, variables and comments in English.

## Stack

- [Vite](https://vite.dev/) + [React](https://react.dev/) (JavaScript, ESLint)
- [vite-plugin-pwa](https://vite-pwa-org.netlify.app/) – service worker, precache, web manifest
- [Dexie](https://dexie.org/) (+ `dexie-react-hooks`) – IndexedDB local database
- [Supabase](https://supabase.com/) (`@supabase/supabase-js`) – cloud sync
- [React Router](https://reactrouter.com/) – routing
- [i18next](https://www.i18next.com/) + `react-i18next` – ES / EN
- [Recharts](https://recharts.org/) – charts

## Getting started

```bash
npm install
npm run dev
```

Other scripts:

```bash
npm run lint      # ESLint
npm run build     # production build (generates the service worker)
npm run preview   # serve the production build (use this to test the PWA / offline mode)
```

The service worker is only generated by `npm run build`; it is not active in `npm run dev`.

## Environment variables

Supabase is optional: without it the app runs in offline-only mode (a warning is logged to the console).

1. Copy `.env.example` to `.env`.
2. Fill in the values from the Supabase dashboard (Project Settings > API):

```
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=
```

`.env` is git-ignored. Never commit it.

## Folder structure

```
public/               PWA icons (icon.svg, pwa-192x192.png, pwa-512x512.png)
src/
  pages/              One file per screen (Login, Home, Vitals, SystemDetail, Alerts,
                      Checkin, Sensors, Comms, Crew, CrewMember)
  components/         Shared UI (Layout, ConnectionStatus)
  data/
    simulator.js      Simulated vital signs
    adapters/         Dataset adapters (dataset rows -> Reading)
    seed/             JSON loaded into IndexedDB on first run
  db/db.js            Dexie schema (AstroHealthDB) + seedIfEmpty()
  rules/engine.js     Thresholds -> alerts
  sync/               Supabase client + sync queue
  bluetooth/          Web Bluetooth heart rate sensor
  auth/               PIN + local session
  i18n/               i18next setup, es.json, en.json
  models/reading.js   Reading type + createReading()
  App.jsx             Routes
  main.jsx            Entry point
```

Conventions:

- All IDs are string UUIDs (`crypto.randomUUID()`), never auto-incremented.
- Create readings only through `createReading()` in `src/models/reading.js`.
- Every user-facing string goes through i18n: add the key to both `es.json` and `en.json`.
- Changing the Dexie schema means adding a new `db.version(n)`; do not edit an existing version.
- `supabase` can be `null`; always check before using it.

## Git workflow

- `main` must always build. Do not commit directly to it.
- One branch per person and task, named `name/task` (e.g. `ana/vitals-screen`).
- Open a Pull Request into `main`; run `npm run lint` and `npm run build` before asking for review.
- Pull `main` often to keep conflicts small:

```bash
git checkout main
git pull
git checkout -b name/task
```
